# GEO Pipeline Runbook

Operational reference for `run-engine.js`. Source-of-truth for selectors is the runner itself; this skill codifies what to check **before** launching and **how to recover** mid-run. Engines tracked: Perplexity, ChatGPT, Google AI Overviews, Gemini, Bing Copilot, Claude, Meta AI. Grok is permanently excluded — do not re-add.

---

## 1. Pre-Flight Checks

Run all four before invoking `brand-geo-monitor`. Halt if any fail — do not proceed and hope.

### 1.1 Chrome CDP port

```bash
curl -s --max-time 2 http://localhost:55068/json/version >/dev/null && echo "CDP OK" || echo "CDP DOWN"
```

If DOWN: ask the user to relaunch Chrome with:
```
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=55068
```
The runner connects to an **already-running authenticated browser**. It does not launch Chrome itself.

`CDP_PORT` env var overrides 55068 if set (see `run-engine.js` line 17).

### 1.2 Per-engine auth (signed-in tabs ready)

Open one tab per engine in the CDP-attached Chrome and confirm the input field is reachable without a sign-in wall:

| Engine | URL | Auth required? | Visual check |
|---|---|---|---|
| Perplexity | https://www.perplexity.ai | No (better with login) | Search box visible |
| ChatGPT | https://chat.openai.com | **Yes** | `#prompt-textarea` present, no "Log in" button |
| Google AIO | https://www.google.com | No | Normal Google search box |
| Gemini | https://gemini.google.com | **Yes** | Composer visible, no "Sign in" link |
| Bing Copilot | https://copilot.microsoft.com | Optional | Composer visible |
| Claude | https://claude.ai | **Yes** | `[data-testid="chat-input"]` present |
| Meta AI | https://www.meta.ai | Optional | Composer visible, no auth modal |

The runner **detects** sign-in walls and marks those prompts `blocked` — it does not log in. Fix auth before launching.

### 1.3 Selector smoke test (optional but recommended after engine UI updates)

Run one throwaway prompt per engine before the full 70-prompt sweep. If selectors have drifted (see section 2), the smoke run fails fast and you can patch `run-engine.js` once instead of mid-batch.

### 1.4 Notion DB IDs and resume state

- Verify `.claude/CLAUDE.md` Notion DB IDs still match the live workspace (`GEO_BRAND_TRACKING_DB_ID` etc.).
- Query Notion for today's `run_date` rows — load the completed `(engine, prompt_id)` set into the resume cache so sub-agents skip already-written pairs.

## 2. Current Working Selectors

Lifted from `run-engine.js`. **Update this table when you patch the runner — both must move together.**

| Engine | Input selector | Response selector / anchor | Login-wall probe |
|---|---|---|---|
| Perplexity | `#ask-input, textarea, [contenteditable="true"]` | `document.querySelector('main')` | none |
| ChatGPT | `#prompt-textarea` | `[data-message-author-role="assistant"]` | `button:has-text("Log in"), button:has-text("Sign up")` |
| Google AIO | candidate scan: `div, section, c-wiz` matched by regex `/AI Overview\|Generated by AI\|Powered by Gemini/i` | first matching candidate's innerText | none — returns `not-shown` if AIO didn't render |
| Gemini | `[contenteditable="true"]` | `document.body.innerText` anchored on "Gemini said" | `a:has-text("Sign in"), button:has-text("Sign in")` |
| Bing Copilot | `textarea, [contenteditable="true"]` | `[data-content="ai-message"], .ac-textBlock, cib-message, [role="article"]` | implicit — `blocked` if input missing |
| Claude | `[data-testid="chat-input"]` | `.font-claude-response-body` grouped under `.standard-markdown` | `button:has-text("Continue with Google"), button:has-text("Sign in")` |
| Meta AI | `div[data-testid="composer-input"][contenteditable], div[contenteditable="true"]:visible` | `.ur-markdown.prose, .ur-markdown` | implicit — `blocked` if composer not clickable |

Meta AI gotcha: there are two `[contenteditable]` elements on the page; **must target the visible one**. Do not simplify the selector to `[contenteditable="true"]`.

Status codes the runner emits per prompt: `ok`, `blocked`, `not-shown` (Google AIO only), `error`. Only `ok` rows are written to Notion.

## 3. Recovery Procedures

### 3.1 Buffered-output freeze (no progress for >5 min)

The runner has a built-in **per-prompt stall watchdog** (`STALL_TIMEOUT_MS`, default 180s). If `engine.run()` does not return within that window, it calls `window.stop()` on the page, navigates to `about:blank`, records the prompt as `status: error` with `error: "stall-timeout after Nms"`, and proceeds to the next prompt. **You no longer need to manually kill the Node process for single-prompt hangs.**

When you still need to intervene (whole-batch hang, multiple consecutive stall-timeouts, watchdog itself unresponsive):

1. **Don't kill the Chrome browser.** Kill only the Node process running `run-engine.js`.
2. Tail the JSONL to find the last completed `(engine, prompt_id)`.
3. Relaunch `run-engine.js` — the resume cache (section 1.4) will skip completed pairs and continue from the next prompt.
4. If the same prompt stall-timeouts twice across runs, mark it `blocked` manually in the run summary and skip it.

Tuning: if a particular engine is legitimately slow (Claude often takes 60–90s due to web search), keep `STALL_TIMEOUT_MS` above that engine's internal `waitUntil` plus buffer. Don't set it below 150000 without testing.

### 3.2 Tab loss / page navigated away

Symptom: `error` rows with messages like "Execution context was destroyed", "Target page closed", or selectors suddenly returning null.

1. Re-open the engine tab in the CDP Chrome at the canonical URL (section 1.2 table).
2. The runner grabs `browser.contexts()[0]` and the first page — if that page changed, results route to the wrong engine. Verify the tab order matches the engine order the runner expects.
3. Resume the runner. The `error`-status prompts will not retry automatically — add them to the "needs manual re-run" list.

### 3.3 Selector drift (engine ships UI update)

Symptom: an entire engine returns 100% `blocked` or `error` despite the tab being signed-in and reachable.

1. In the CDP Chrome, open DevTools on the affected engine, manually type a prompt, and inspect the input element and the rendered response element.
2. Update the matching row in section 2 of this skill **and** the corresponding line in `run-engine.js`.
3. Run the section 1.3 smoke test before resuming the full sweep.

### 3.4 Rate-limit dialog (ChatGPT specifically)

Runner detects `/Too many requests|You're making requests too quickly/i` and marks the prompt `blocked`. If this fires on >3 prompts in a row:
- Pause the runner for 10 minutes.
- Optionally raise `INTER_PROMPT_MS` from 1500ms to 3000ms.
- Resume.

### 3.5 Notion 429 / 503 during write-back

Batch writes by engine (write all 70 rows for engine 1, then engine 2). On persistent 429: insert a 2s pause between batches. On 503: pause 60s and retry the same batch — Notion 503s are usually transient.

## 4. Fallback Decision Rule

When one engine stalls mid-sweep, decide in this order:

1. **Single prompt stuck (>2 min on one prompt)** → kill the Node process, resume (section 3.1). Cost: ~30s.
2. **Same engine fails ≥5 prompts in a row with `error`** → suspected selector drift or tab loss. Run section 3.2 then section 3.3. **Do not skip the engine entirely yet.** Coverage matters; a patched engine is better than a missing column.
3. **Same engine fails ≥10 prompts after a 3.2+3.3 attempt** → skip the engine for this run. Mark all its remaining prompts `blocked` in the run summary under "Engine offline — coverage gap". Continue with the other 6 engines.
4. **≥3 engines failing simultaneously** → abort the run. Likely a Chrome / CDP / network problem upstream of any single engine. Run section 1.1, fix the root cause, restart from resume state.

**Never abort the whole sweep for one engine.** The Synthesizer can compute partial-coverage metrics; it can't compute anything from zero data. A 6-engine run is better than no run.
