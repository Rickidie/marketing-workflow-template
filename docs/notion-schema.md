# Notion Database Schemas

This file describes the schema for each of the 8 Notion databases used by the agent pipeline. Create each database manually in your Notion workspace, then copy its ID from the URL and paste it into `.env`.

**How to find a database ID:**
Open the database in Notion → look at the URL: `https://www.notion.so/{workspace}/{DATABASE_ID}?v={view_id}`. The 32-character hex string before the `?` is the ID.

**How to connect your Notion integration:**
After creating each database, open it → click the `...` menu → Connections → search for your integration and add it. Without this step, the agents cannot read or write.

## 1. GEO Brand Tracking DB

**Env variable:** `GEO_BRAND_TRACKING_DB_ID`
**Written by:** `brand-geo-monitor` agent
**Read by:** `geo-intelligence-synthesizer` agent

One row per prompt × engine × run date. This is the raw data table — ~490 rows per weekly monitoring run (70 prompts × 7 engines).

| Property name | Type | Notes / Select options |
|---|---|---|
| `prompt_id` | Title | Prompt identifier, e.g. "C-01", "P-07". Do not rename — used as the row key. |
| `prompt_text` | Text (Rich Text) | Exact prompt text as written in `_context/geo-prompt-universe.md` |
| `prompt_category` | Select | `Brand/Product`, `Category`, `Use Case`, `Competitor`, `Technical` |
| `engine` | Select | `Perplexity`, `ChatGPT`, `Google AI Overviews`, `Gemini`, `Bing Copilot`, `Claude`, `Meta AI` |
| `run_date` | Date | Date the monitoring run was executed (Monday) |
| `brand_mentioned` | Checkbox | true if the brand name appears in the response |
| `brand_cited` | Checkbox | true if the brand has a hyperlink or explicit attribution |
| `citation_url` | URL | Full URL of the citation, if present; empty otherwise |
| `share_of_voice` | Number | 0–100. Formula: (brand name appearances) / (all named vendor appearances) × 100 |
| `prompt_win` | Select | `Win`, `Loss`, `Not Mentioned` |
| `citation_position` | Select | `First`, `Secondary`, `Passing` |
| `citation_quality` | Select | `Direct Quote`, `Paraphrase`, `Name Only` |
| `link_destination` | Select | `Homepage`, `Product Page`, `Blog`, `None` |
| `sentiment` | Select | `Positive`, `Neutral`, `Negative`, `Not Mentioned` |
| `accuracy` | Select | `Accurate`, `Inaccurate`, `Partial` |
| `competitors_present` | Multi-select | Comma-separated competitor names found in the response. Add options as you discover competitors. |
| `raw_response_excerpt` | Text (Rich Text) | First ~700 characters of the AI engine's response |
| `notes` | Text (Rich Text) | Anomaly flags, disambiguation notes, or other observations |

## 2. Website Audit Log DB

**Env variable:** `WEBSITE_AUDIT_LOG_DB_ID`
**Written by:** `website-geo-auditor` agent
**Read by:** `geo-intelligence-synthesizer` agent (reads open issues)

One row per issue per page per audit date. The auditor crawls the site and logs every GEO, AEO, SEO, and content gap finding.

| Property name | Type | Notes / Select options |
|---|---|---|
| `issue_id` | Title | Auto-generated by the agent: "AUDIT-001", "AUDIT-002", etc. |
| `page_url` | URL | Full URL of the page with the issue |
| `audit_date` | Date | Date the audit was run |
| `issue_type` | Select | `GEO`, `AEO`, `SEO`, `Content Gap`, `Technical` |
| `severity` | Select | `Critical`, `High`, `Medium`, `Low` |
| `issue_description` | Text (Rich Text) | What the problem is (specific, not generic) |
| `recommendation` | Text (Rich Text) | What to do to fix it (specific and actionable) |
| `effort_estimate` | Select | `Low (< 1 day)`, `Medium (1–3 days)`, `High (3+ days)` |
| `status` | Select | `Open`, `In Progress`, `Resolved` |
| `assigned_to` | Person | Who is responsible for the fix |
| `resolution_notes` | Text (Rich Text) | Notes on how the issue was resolved |
| `resolved_date` | Date | Date the issue was resolved |

## 3. Keyword Research DB

**Env variable:** `KEYWORD_RESEARCH_DB_ID`
**Written by:** `research-analyst` agent (creates rows), `geo-intelligence-synthesizer` agent (scores and updates)
**Read by:** `geo-intelligence-synthesizer`, `content-creator`

The keyword pipeline. Each row is a keyword bet with scoring fields that are updated weekly by the Synthesizer.

| Property name | Type | Notes / Select options |
|---|---|---|
| `keyword` | Title | The keyword or phrase being tracked |
| `type` | Select | `GEO`, `AEO`, `SEO` |
| `difficulty` | Select | `High`, `Medium`, `Low` — based on SERP competition |
| `geo_relevance_score` | Number | 1–10: how likely this keyword triggers an AI engine answer |
| `associated_prompts` | Multi-select | Prompt IDs from `_context/geo-prompt-universe.md` (e.g. "C-01", "U-03"). Required — at least one prompt per keyword. |
| `competitor_wins` | Text (Rich Text) | Which competitors rank or appear for this keyword |
| `last_checked` | Date | Date research was last run |
| `recommended_content_type` | Select | `Blog Post`, `Landing Page`, `FAQ Page`, `Comparison Page`, `Glossary Entry` |
| `status` | Select | `New`, `In Progress`, `Active`, `Re-angle`, `Retired` |
| `notes` | Text (Rich Text) | Research notes and observations |
| `baseline_win_rate` | Number | Mean win rate across associated prompts in the 4 weeks before first content shipped. Set once, never recomputed. (Written by Synthesizer.) |
| `current_win_rate` | Number | Mean win rate across associated prompts over the last 4 monitoring runs. (Written by Synthesizer.) |
| `prompt_impact_score` | Number | 0–10 composite score per the scoring model in `.claude/rules/scoring-model.md`. (Written by Synthesizer.) |
| `first_content_ship_date` | Date | Date the first content piece targeting this keyword was published. (Written by Synthesizer.) |
| `last_scored` | Date | Date the Synthesizer last computed `prompt_impact_score`. (Written by Synthesizer.) |
| `content_pieces_shipped` | Number | Count of published content pieces targeting this keyword. (Written by Synthesizer.) |

**Note on `content_pieces_shipped`:** This can also be implemented as a Relation to Content Performance DB, with a Rollup counting Published rows. Both approaches work. If using a plain Number, the Synthesizer writes the count directly.

## 4. Competitor Intelligence DB

**Env variable:** `COMPETITOR_INTELLIGENCE_DB_ID`
**Written by:** `research-analyst` agent
**Read by:** `geo-intelligence-synthesizer` agent

Tracks competitor GEO presence — which competitors appear in AI responses, on which engines, and with what content angles.

| Property name | Type | Notes / Select options |
|---|---|---|
| `competitor_name` | Title | Name of the competitor |
| `prompt` | Text (Rich Text) | The query used to surface the competitor |
| `engine` | Select | `Exa`, `Perplexity`, `ChatGPT`, `Google AI Overviews`, `Gemini`, `Bing Copilot`, `Claude`, `Meta AI` |
| `date` | Date | Date the intelligence was gathered |
| `brand_mentioned` | Select | `Yes`, `No` — whether your brand was also mentioned alongside the competitor |
| `share_of_voice` | Number | Competitor's estimated share of voice in the response (0–100%) |
| `notable_citation_url` | URL | URL of the competitor's most-cited page |
| `content_type_winning` | Select | `Blog Post`, `Landing Page`, `Documentation`, `Whitepaper`, `Product Page` |
| `key_takeaway` | Text (Rich Text) | Summary of what the competitor is winning and why |
| `recommended_action` | Text (Rich Text) | What the brand should do in response |

## 5. Content Performance DB

**Env variable:** `CONTENT_PERFORMANCE_DB_ID`
**Written by:** `content-creator` agent (creates rows), `content-reviewer` agent (updates status)
**Read by:** `geo-intelligence-synthesizer` agent

Inventory of all content pieces shipped. Each row is one piece (blog, LinkedIn post, X post). The Synthesizer uses this to reconcile keyword-content linkage for scoring.

| Property name | Type | Notes / Select options |
|---|---|---|
| `content_title` | Title | Title of the content piece |
| `type` | Select | `Blog Post`, `LinkedIn`, `Twitter/X` |
| `brief_source` | Text (Rich Text) | Content Calendar entry ID that generated this piece |
| `status` | Select | `Drafted`, `In Review`, `Approved`, `Published`, `Rejected` |
| `file_path` | Text (Rich Text) | Absolute disk path to the saved `.docx` file. Must be a real, verified path. |
| `publish_date` | Date | Date the content was published |
| `target_keywords` | Text (Rich Text) | Comma-separated keywords this piece targets (used by Synthesizer for keyword-content linkage) |
| `notes` | Text (Rich Text) | Reviewer verdict, revision notes, or other observations |

**Note:** The `geo_impact_score` field is deprecated. Do not create it. Keyword effectiveness is tracked in Keyword Research DB via `prompt_impact_score`. Content Performance is an inventory table only.

## 6. Content Briefs DB

**Env variable:** `CONTENT_BRIEFS_DB_ID`
**Written by:** `geo-intelligence-synthesizer` agent (generates briefs) and the Vercel dashboard (stub briefs)
**Read by:** `content-creator` agent, `geo-intelligence-synthesizer` (enriches stubs)

One row per content brief. Briefs are created by the Synthesizer each Tuesday and consumed by the content-creator.

| Property name | Type | Notes / Select options |
|---|---|---|
| `title` | Title | Brief title (becomes the article headline or social topic) |
| `brief_text` | Text (Rich Text) | Full brief content: audience, problem, angle, key points, GEO angle (which prompts to win), AEO angle, competitor angle, required elements. Stub briefs from the dashboard contain the literal string `[STUB:NEEDS-ENRICHMENT]` here until the Synthesizer enriches them. |
| `target_keywords` | Text (Rich Text) | Target keyword(s) for this piece |
| `target_prompts` | Text (Rich Text) | Comma-separated prompt IDs from `_context/geo-prompt-universe.md` |
| `content_type` | Select | `Blog Post`, `Both Social` (LinkedIn + X), `LinkedIn`, `Twitter/X` |
| `priority` | Select | `High`, `Medium`, `Low` |
| `status` | Select | `Open`, `In Progress`, `Drafted`, `Completed`, `Cancelled` |
| `source` | Select | `Original`, `Repurpose` |
| `created_by` | Select | `GEO Synthesizer`, `Manual` |

## 7. Content Calendar DB

**Env variable:** `CONTENT_CALENDAR_DB_ID`
**Written by:** `geo-intelligence-synthesizer` agent (7 entries per week)
**Read by:** `content-creator` agent

One row per scheduled content piece per week. The Synthesizer populates this every Tuesday for the coming week. The content-creator reads these entries and executes them.

| Property name | Type | Notes / Select options |
|---|---|---|
| `title` | Title | Content piece title |
| `brief_text` | Text (Rich Text) | Brief content (same structure as Content Briefs DB) |
| `target_keywords` | Text (Rich Text) | Target keyword(s) |
| `target_prompts` | Text (Rich Text) | Comma-separated prompt IDs |
| `content_type` | Select | `Blog Post`, `Both Social`, `LinkedIn`, `Twitter/X` |
| `priority` | Select | `High`, `Medium`, `Low` |
| `status` | Select | `Scheduled`, `Drafted`, `In Review`, `Approved`, `Published`, `Skipped` |
| `source` | Select | `Original`, `Repurpose` |
| `created_by` | Select | `GEO Synthesizer`, `Manual` |
| `scheduled_date` | Date | Publication date (Mon/Wed/Fri for blogs; Mon–Sun for social) |
| `file_path` | Text (Rich Text) | Disk path added by content-creator after draft is saved and verified |

## 8. Keyword Score History DB

**Env variable:** `KEYWORD_SCORE_HISTORY_DB_ID`
**Written by:** `geo-intelligence-synthesizer` agent (one row per keyword per week, appended)
**Read by:** `geo-intelligence-synthesizer` (trend analysis across 4-week windows)

Time-series table. The Synthesizer appends one row per keyword per Tuesday run. Never overwrites existing rows — only appends. Used for 4-week slope calculation and trend classification (Trending Up / Trending Down / Flat).

| Property name | Type | Notes / Select options |
|---|---|---|
| `Snapshot` | Title | Unique key: `{keyword-slug}-{YYYY-MM-DD}`, e.g. "aml-compliance-platform-2026-05-12" |
| `Keyword` | Relation | Links to the Keyword Research DB row. Required. |
| `Week Start Date` | Date | Monday of the monitoring run that generated this snapshot |
| `Win Rate` | Number | Mean win rate across the keyword's associated prompts for this week (0–100) |
| `Prompt Impact Score` | Number | Computed score per scoring model (0–10) |
| `Delta vs Baseline` | Number | `current_win_rate − baseline_win_rate` in percentage points |
| `Pieces Shipped At Snapshot` | Number | Count of `content_pieces_shipped` at the time of this snapshot |
| `Engines Won` | Number | Count of AI engines (out of 7) that had at least one win on the keyword's associated prompts in this week's run |

**Uniqueness:** Before appending, the Synthesizer checks whether a row already exists for the same (keyword, week). If it does, the append is skipped — runs are idempotent.
